# Итоговый отчёт: модернизация в потоковую систему мультикамерного 3D-трекинга

Ветка `claude/lucid-davinci-vuf745`, ноябрь 2026. Задание — «Модернизация проекта
tracking_and_trajectory: высокоточный мультикамерный 3D-трекинг в реальном времени».

> **Главное ограничение этой работы.** В среде разработки не было видео пяти камер, весов YOLO
> (`models/best.pt`), 3D-модели (`models/CargoTruck.fbx`), GPU и PyTorch; доступ к Google Drive с видео
> закрыт сетевой политикой окружения. Поэтому **все числа ниже получены на синтетических данных**
> (`tools/make_synthetic_data.py`: коробка 16.5 × 2.55 × 4 м по петле, 5 камер, детекции с шумом,
> перекрытиями, пропусками и ложными рамками; без YOLO). Они показывают поведение алгоритмов и
> относительный выигрыш вариантов, **а не точность на реальном видео**. Числа по реальным данным
> для прежней системы — в README (последний полный прогон до модернизации: точка CSV медиана 2.20 м,
> p95 7.14 м). Режимы с YOLO (`replay`, `live`) проверены только на синтетических видеофайлах с
> готовыми детекциями (тест `test_video_replay_with_pacing_and_dropping`).

### Частично

- **Ориентация объекта.** Курс — отдельная переменная с динамикой (цель — направление сглаженной
  скорости, предел скорости поворота по Аккерману `v / R_min`, удержание при остановке), но
  по-прежнему выводится из движения, а не измеряется: рамка одинакова при повороте модели на 180°,
  а измерение по силуэту маски не реализовано.
- **Одна камера.** По умолчанию трек без второй камеры не стартует (ТЗ: не выдавать недостоверные
  координаты). Опция `tracker.mono_init` даёт старт по высоте рамки с меткой `quality = mono`:
  на синтетике ошибка ~30 м (глубина по одной камере не наблюдаема).
- **Ложные детекции.** Гейт рамок и контроль расходимости с переинициализацией снижают медиану, но
  при 8 % ложных рамок плохая инициализация всё ещё даёт эпизод с ошибкой в десятки метров до
  переинициализации (см. сценарий `false_detection`).
- **Производительность YOLO** (GPU, FP16, ONNX/TensorRT, батчи) — реализован пакетный вызов и флаг
  `detector.half`; измерить и оптимизировать без весов и GPU невозможно.
- **Разбиение данных** на обучение/валидацию/тест: реализована оценка на отложенных кадрах
  (`--test-frames`), но независимых данных нет: YOLO обучена на тех же видео, геометрия модели
  калибровалась по эталону (см. раздел 6).

### Не удалось проверить

- Точность и производительность на реальных видео (нет данных в среде).
- Инференс YOLO: FPS, задержка, загрузка GPU.
- Видео с наложением на реальных кадрах (путь проверен на синтетических видеофайлах).

## 2. Архитектура

Подробно: `docs/ARCHITECTURE.md`. Кратко: кадры → `Synchronizer` → `CameraScheduler` (кого
детектировать) → детектор (YOLO пакетно / готовые детекции) → `fusion` (согласованные центроиды →
триангуляция с ковариацией) → `CabTracker` (IEKF: рёбра силуэта модели + 3D-точка, dt, пределы, гейт,
контроль расходимости, курс) → `StreamingBSpline` (фоновый поток) → запись (`stream_track.csv`,
`smoothed_track.csv`, `performance_report`, графики, видео).

Список файлов: новые — `pipeline/config.py`, `pipeline/streaming.py`, `pipeline/variants.py`,
`pipeline/stream_plots.py`, `reconstruction/fusion.py`, `reconstruction/camera_scheduler.py`,
`reconstruction/streaming_bspline.py`, `stream.py`, `tools/run_scenarios.py`, `tools/__init__.py`,
`tests/test_fusion.py`, `tests/test_camera_scheduler.py`, `tests/test_streaming_bspline.py`,
`tests/test_streaming.py`, `docs/ARCHITECTURE.md`, `docs/FINAL_REPORT.md`, `docs/results/`;
изменённые — `reconstruction/visibility.py`, `tools/make_synthetic_data.py`, `tests/test_visibility.py`,
`main.py`, `README.md`, `CLAUDE.md`. Тяжёлых зависимостей не добавлено (numpy, scipy, opencv, matplotlib).

## 6. Точность и валидация: честные оговорки

- Независимой тестовой выборки нет. YOLO (`models/best.pt`) обучена на тех же пяти видео; масштаб
  актора ×3.186 и точка CSV на модели калиброваны по эталонной траектории. Параметры трекера (СКО
  ребра 20 px, пределы ускорения) ранее подбирались по CSV цели на реальных данных; параметры
  сплайна (λ) и планировщика — на синтетике. Поэтому ни одно число нельзя выдавать за оценку
  обобщения; `pipeline/variants.py --test-frames` позволяет оценивать только отложенные кадры,
  когда появятся независимые записи.
- Эталонный CSV нигде не входит в алгоритм реального времени: он читается только в оценке
  (`variants.py`, `stream_plots.py`, `main.py compare`) и для метки на видео.
- Все измерения выше — фактические прогоны кода на синтетических данных; ничего не подменено расчётными оценками.

## 7. Производительность (фактические измерения, CPU 4 ядра, без GPU)

Режим `detections` (детекция — чтение готовых детекций), базовая синтетика, конфигурация по умолчанию
(планировщик, согласованная триангуляция, сплайн в фоне), `docs/results/synthetic/stream/performance_report.md`:

- выдача 3D-координат: 143 /с (1001 тик за 7.0 с); задержка кадр → оценка: средняя 23.9 мс, p50 26.5, p95 38.1 мс
  (без темпа кадров: задержка включает ожидание в очереди без потерь; при темпе 30 FPS тик 7 мс);
- время этапов (среднее / p95): планировщик 2.4 / 4.2 мс, фильтр 3.5 / 6.2 мс, сплайн в основном потоке 0.7 / 1.1 мс,
  тик 6.8 / 11.0 мс; подгонка сплайна (фоновый поток) 0.40 мс, нарушений бюджета 25 мс — 0;
- планировщик: 3.16 активных камер из 5, доля детектируемых кадров 0.69 (экономия 31 % вызовов YOLO);
- память 98 МБ; пропусков кадров 0 (режим без потерь).

Целевые 20–30 обновлений/с для пяти камер достижимы для части конвейера без YOLO (7 мс на тик);
стоимость YOLO на пяти потоках не измерена — это главный неизмеренный фактор. Оценка: при CPU-инференсе
YOLO26s-seg 960 px порядка 100–300 мс/кадр на камеру (не измерено здесь!) планировщик, сокращающий
число детекций до ~2.7 на тик, не даст 30 FPS без GPU; с GPU и батчем из 3 кадров — вероятно, даст.

## 9. Ограничения

1. Ориентация из движения; при медленном резком повороте ошибка курса остаётся (на реальных данных —
   кадры ~650–850). Следующий шаг — измерение по силуэту маски (маски сохраняются).
2. Один объект: детектор берёт объект с максимальной уверенностью; несколько объектов потребуют
   сопоставления и управления треками (`CabTracker` готов как единица для `MultiTracker`).
3. Участки одной камеры: глубина не наблюдаема; без рельефа дороги или ключевых точек ошибка
   десятки метров (сценарии `handover`, `cam1_mono`).
4. Плохая инициализация при ложных детекциях даёт эпизод до переинициализации.
5. Число кадров (1001) и размер кадра — в конфигурации; для другой сцены их надо задать.
6. Пуш в GitHub из облачной сессии невозможен (403), коммиты локальные.

## 10. Запуск

```bash
# демонстрация в реальном времени на записанных видео (нужны tmp/project2, models/best.pt, models/CargoTruck.fbx)
.venv/bin/python stream.py replay --data tmp/project2 --video

# живые потоки
.venv/bin/python stream.py live --config configs/live.json      # cameras.live_sources = {"1": "rtsp://...", ...}

# без YOLO: алгоритмы и метрики на готовых детекциях
.venv/bin/python stream.py detections --data tmp/project2 --detections outputs/main/detections --no-pacing
.venv/bin/python stream.py variants --data tmp/project2 --detections outputs/main/detections
.venv/bin/python stream.py scenarios                              # синтетика

# офлайн-конвейер и сравнение методов (как раньше)
.venv/bin/python main.py
```

нет видео). Графики: `docs/results/synthetic/stream/plots/*.png`, `docs/results/synthetic/variants/*.png`,
`docs/results/synthetic/compare/*.png`.

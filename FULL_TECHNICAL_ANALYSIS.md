# Полный технический разбор проекта «Пеленг» (tracking_and_trajectory)

Дата: 4 ноября 2026. Ветка `feature/camera-intrinsics` от `master` (ed1b95e).

## 1. Назначение и поток данных

По синхронным видео нескольких неподвижных/движущихся камер Unreal Engine восстанавливается 3D-траектория
грузовика. Основной результат — **система реального времени**: оценка на кадре t использует только кадры ≤ t.

```
CSV камеры N ──► read_camera_csv ──► позиция, углы, фокус (мм) по кадрам ─┐
видео камеры N ─► probe_video_resolution ─► W × H этой камеры ────────────┼─► Camera.from_physical ─► K, R, C
                                                                          │
видео ─► детектор (YOLO detection/yolo.py | classic) ─► рамка, маска, центроид (пиксели этого видео)
         └─► detections/cam{N}.csv, cam{N}_polygons.npz, meta.json (+ image_size по камерам)
                         │
                         ▼
   main.py (pipeline/run.py):  center (офлайн триангуляция центров масок → B-сплайн)
                               optimize / cab (офлайн, заглядывают вперёд — только сравнение)
                               realtime  ОСНОВНОЙ: CabTracker (reconstruction/visibility.py)
                               approx, compare, video
   stream.py (pipeline/streaming.py): источники кадров (replay/live/detections) → Synchronizer →
        CameraScheduler (ACTIVE/PROBE/SLEEP) → детектор → CabTracker → StreamingBSpline →
        stream_track.csv, trajectory.csv, performance_report
```

Модули: `reconstruction/camera.py` (модель камеры, CSV камер), `data_io.py` (пути, разрешение видео, CSV цели),
`triangulation.py`, `fusion.py` (3D-точка реального времени и её ковариация), `visibility.py` (фильтр
Калмана: состояние — центр модели и скорость, измерения — рёбра рамки проекции 3D-модели/коробки и
3D-точка), `camera_scheduler.py`, `streaming_bspline.py`, `cab_model.py`, `truck_model.py`/`fbx_reader.py`,
`orientation.py`, `silhouette_fit.py`, `ground.py`, `approximation.py`.

## 2. Математика камеры

Система мира Unreal: левая, Z вверх, единицы — см (`units_per_meter = 100`). Углы Rotator (roll, pitch, yaw)
в градусах в CSV, в коде — радианы. Оси камеры (`camera_axes`):

```
forward = (cp·cy, cp·sy, sp)
right   = (sr·sp·cy − cr·sy, sr·sp·sy + cr·cy, −sr·cp)
up      = (−(cr·sp·cy + sr·sy), cy·sr − cr·sp·sy, cr·cp)
R = [right; −up; forward]  (мир → камера),  X_c = R (P − C)
u = c_x + f_x · X_c / Z_c,  v = c_y + f_y · Y_c / Z_c,  Z_c ≤ 0 → NaN (за камерой)
```

Внутренняя матрица `K = [[f_x, 0, c_x], [0, f_y, c_y], [0, 0, 1]]`:

```
f_x = f_мм · W_px / 23.76,   f_y = f_мм · H_px / 13.365,   c_x = W/2,   c_y = H/2
```

Матрица 23.76 × 13.365 мм постоянна; W × H — фактическое разрешение видео этой камеры. Физический фокус
от разрешения не зависит; пиксельный масштабируется линейно (проверено тестом: проекция камеры 960×540 —
ровно половина проекции 1920×1080, лучи `K⁻¹(u, v, 1)` совпадают). При 1920×1080: 80.81 px/мм по обеим осям
(пиксели квадратные). Формулы верны, если кадр — вся матрица без обрезки: поэтому кадр с другим соотношением
сторон (например, 1920×1088 или 4:3) отклоняется с ошибкой (допуск 0.5 %).

Масштабирование внутри детекторов: YOLO (ultralytics) возвращает рамки и полигоны в координатах исходного
кадра (`orig_shape`), letterbox до `imgsz` внутренний — повторного пересчёта нет. Классический детектор
работает на уменьшенном кадре и использует `K_small = diag(s, s, 1) · K` — одно согласованное
преобразование. Наложения в `tools/demo_live.py` масштабируются по размеру кадра каждой камеры.

## 3. Данные (проверено на файлах)

1932 кадра (метаданные совпадают с декодированным кадром). CSV камер: CP1251/ASCII, `;`, CRLF,

## 4. Найденные проблемы и исправления

| # | Проблема | Последствие | Исправление |

| 3 | `cameras.sensor_*_mm` в конфигурации не использовались, но выглядели настраиваемыми | Ложное ощущение, что матрицу можно менять | Константа в camera.py; старые ключи принимаются, только если равны константе |
| 4 | Видео искались по имени `Way1.…` | Видео сцены 2 (`Way2.…`) не находились | Шаблон `*.FinalImage.CineCameraActor{N}.mp4`, неоднозначность — ошибка |

| 7 | Края кадра в трекере/планировщике/рамках — общие для всех камер | Неверные флаги обрезки рамки у камер другого разрешения | Размер берётся у объекта Camera |

Не исправлено (вне задачи, отмечено): `main.py` требует веса YOLO даже при `--detector classic`;
`NUM_VIDEO_FRAMES = 1001` в pipeline/center.py — офлайн-шаги main.py обрабатывают только первые 1001 кадр
(для сцены 2 это не вся запись; потоковая система `stream.py` от этого не зависит); офлайн-шаги и
compare требуют CSV цели; замеры скорости в autotune/benchmark используют тестовый кадр 1920×1080 (это не
параметр камеры).

# Пеленг: 3D-траектория грузовика по видео пяти камер

По синхронным видео пяти камер (Unreal Engine, 1920×1080, 30 FPS, 1001 кадр) восстанавливается
3D-траектория грузовика, его скорость и положение центра кабины. Основной результат считается
**в реальном времени**: оценка на кадре t использует только кадры ≤ t.

## Быстрый старт

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# данные: 5 видео Way1.FinalImage.CineCameraActor{1..5}.mp4 и 6 CSV object_transform_*.csv
#   -> tmp/project2/ (папка в .gitignore), или укажите --data
# модели: models/best.pt (YOLO) и models/CargoTruck.fbx (3D-модель), см. models/README.md

.venv/bin/python main.py                  # полный прогон со всеми шагами и видео, ~2 мин (+ ~3.5 мин детекция при первом запуске)
.venv/bin/python main.py --no-video       # то же без видео
.venv/bin/pytest -q                       # тесты (тесты на реальных данных пропускаются, если данных нет)
```

Отдельные шаги переиспользуют результаты с диска:

```bash
.venv/bin/python main.py --steps realtime,approx,compare --video   # трекер, базовая аппроксимация, отчёт, видео
.venv/bin/python main.py --redetect                               # пересчитать детекции (новые веса)
.venv/bin/python main.py --cameras 1,2,3                          # произвольный набор камер
.venv/bin/python main.py --help                                   # все параметры
```

Без видео, весов и 3D-модели пайплайн можно проверить на синтетической сцене в формате проекта:

```bash
python tools/make_synthetic_data.py --data tmp/synthetic --out outputs/synthetic
python main.py --data tmp/synthetic --out outputs/synthetic --no-video
```

В конце шага `compare` в консоль печатается сводка метрик по всем вариантам (та же таблица —
`metrics_summary.csv`). Обзор кода, последовательность действий и предложения по точности —
[docs/PIPELINE_REVIEW.md](docs/PIPELINE_REVIEW.md).

## Как обрабатывается видео

```
 видео ×5 ──► detect (YOLO-seg) ──► detections/cam{N}.csv: рамка, центр маски, уверенность, флаги
                                         │
             ┌───────────────────────────┼──────────────────────────────────────────┐
             │ ОФЛАЙН (весь видеоряд, для сравнения)       │ РЕАЛЬНОЕ ВРЕМЯ (основной)  │
             ▼                                             ▼                            │
  center: центр маски ─► триангуляция по кадрам   realtime: по кадрам по порядку        │
          ─► начальный B-сплайн                     1. прогноз (постоянная скорость)    │
             │                                      2. рёбра, закрытые препятствием ─► в│
             ├─► optimize: сплайн по пикселям          сторону                          │
             │   всех камер (Huber + рывок)          3. обновление по рамкам: проекция  │
             └─► cab: коробка, подогнанная ко           3D-модели грузовика              │
                 всем рамкам всего видео             4. физические пределы ускорения    │
                                                     5. нет детекций — прогноз          │
             │                                             │                            │
             └──────────────────────► compare ◄────────────┘                            │
                     CSV цели (только для оценки): report.md, metrics.json, графики     │
                                       │                                                │
                                       └─► video: силуэт модели, центр кабины, след ────┘
```

| Шаг | Что делает | Модуль | Результат в `outputs/main/` |
|---|---|---|---|
| `detect` | YOLO на каждом кадре каждой камеры; на кадр — объект с максимальной уверенностью; флаги «касается края», «маска мала», «ненадёжно» | `pipeline/detect.py`, `detection/` | `detections/cam{N}.csv`, `cam{N}_polygons.npz`, `meta.json` |
| `center` | Офлайн. Центр маски → робастная триангуляция → начальный B-сплайн; проверка смещения кадров видео ↔ CSV; отчёт по базовому варианту | `pipeline/center.py` | `center/report.md`, `center/plots/`, `center_spline.npz` |
| `optimize` | Офлайн. Контрольные точки сплайна центра маски по пикселям всех камер (least_squares, Huber, ускорение и рывок) | `reconstruction/optimizer.py` | `optimized_spline.npz` |
| `cab` | Офлайн. Коробка с подбираемыми габаритами по рамкам всего видео; точка — передняя грань / центр кабины | `reconstruction/cab_model.py` | `cab_spline.npz`, `cab_center_spline.npz` |
| `realtime` | **Основной.** Фильтр Калмана по кадрам, только прошлое; измерение — рамка проекции 3D-модели; обработка потери видимости | `reconstruction/visibility.py`, `truck_model.py` | `realtime_track.npz` |
| `approx` | Базовый вариант без модели объекта: «обычная аппроксимация» 3D-точек триангуляции полиномом — причинный по окну прошлых кадров (реальное время; без точек — прогноз по прямой) и один полином по всем точкам (офлайн) | `reconstruction/approximation.py` | `approx_track.npz` |
| `compare` | Все варианты против CSV цели: положение (медиана/p95/RMSE/макс, MAE, по осям X/Y/Z), смещение в осях грузовика, скорость, скачки скорости, ошибка по числу камер и по статусу кадра, калибровка погрешности трекера (СКО фильтра против ошибки); графики: ошибка по кадрам, вид сверху, скорость, сводка, рёбра, **координаты от времени** (07), **аппроксимация против трекера** (08), **погрешность** (09); вид сверху с секторами камер и препятствиями (`06`, `pipeline/coverage.py`); сводка в консоль | `pipeline/run.py` | `report.md`, `metrics.json`, `metrics_summary.csv`, `compare/*.png` |
| `video` | Наложение на каждое видео: силуэт модели, центр кабины, след (только прошлое), статус кадра. Включено при полном прогоне (`--no-video` — пропустить), при `--steps` добавляется флагом `--video` | `pipeline/run.py` | `videos/realtime_cam{N}.mp4` |

`center` выполняется всегда, когда нужны `optimize`, `cab`, `approx`, `compare` или `video`: его сплайн — начальное
приближение для `cab`, его 3D-точки — вход `approx`, а его метрики входят в сравнение.

### Трекер реального времени (`reconstruction/visibility.py`)

На каждом кадре по порядку:

1. **Прогноз.** Состояние — центр 3D-модели и вектор скорости, модель «постоянная скорость».
   Курс — направление скорости (отдельной переменной нет: рамка почти не меняется при повороте
   грузовика на 180°, и фильтр с курсом в состоянии «переворачивал» его). Шум процесса разный
   вдоль и поперёк движения.
2. **Закрытые рёбра.** Прогнозная рамка сравнивается с рамкой YOLO. Ребро, ушедшее внутрь при
   совпадающем противоположном, — грузовик заезжает за препятствие; ребро не используется.
   Ребро у края кадра не используется всегда.
3. **Обновление.** Рёбра рамок всех камер кадра против рамки проекции выпуклой оболочки 3D-модели;
   итерированное обновление, Хьюбер; вес по уверенности; камера, только что снова увидевшая
   грузовик, первые 10 кадров входит с пониженным весом. Рамки поправляют только положение центра.
4. **Пределы.** Изменение скорости за кадр — не больше 12 м/с² вдоль и 8 м/с² поперёк;
   поправка положения — не больше 1.5 м за кадр. Поэтому при появлении грузовика скорость не скачет.
5. **Нет детекций** — только прогноз по вектору скорости, неопределённость растёт, точка не пропадает.

Статус кадра: `initializing` (нужно 8 кадров с ≥2 камерами для начальной скорости), `measured`,
`partial` (рёбра закрыты), `predicted` (детекций нет). На выходе: точка CSV цели и центр кабины
(из геометрии модели), скорость, курс, СКО положения, число камер.

## Данные и соглашения

- **Координаты** — Unreal Engine: левая система, Z вверх, сантиметры (`--units-per-meter 100`).
- **CSV** — CP1251, разделитель `;`, CRLF. Камеры: `Frame;Loc_X;Loc_Y;Loc_Z;Rot_Roll;Rot_Pitch;Rot_Yaw`,
  фокус в первой строке, углы в градусах. Поза камеры берётся из строки с номером кадра.
- **CSV цели** `object_transform_SM_AA_track.csv` — только для оценки, не вход алгоритма.
  Испорченные ячейки (кадр 402 `Loc_X = 'авг.13'`, кадр 691 `Loc_Y = 'июл.25'`) не угадываются:
  NaN, кадр исключается из оценки, причина пишется в отчёт.
- **Кадры**: видео 1001 кадр, CSV 1002 строки; `--frame-offset` (кадр CSV = кадр видео + смещение),
  по проверке лучшее 0 (0 и +1 на этих данных почти не различаются).
- **Камеры 1–4 неподвижны**, Camera5 поворачивается по yaw на кадрах 565–960 и проходит ±180°
  (между 623 и 624) — поза всегда берётся по кадру. Номера камер задаются `--cameras` (по умолчанию 1–5);
  число кадров (1001) и размер кадра пока константы.
- **Модель камеры**: `fx = focal_mm / 23.76 * 1920`, `fy = focal_mm / 13.365 * 1080`, `cx = 960`, `cy = 540`;
  `u = cx + fx·(d·right)/z`, `v = cy − fy·(d·up)/z`, `z = d·forward`, `d = P − C`.
- **Детекция** (`detections/cam{N}.csv`, `detection/schema.py`): `camera, frame, confidence, x1..y2,
  point_u, point_v, point_source, mask_area_px, mask_centroid_*, keypoint_* (под YOLO-pose),
  num_candidates, edge_clipped, too_small, unreliable`.
- **3D-модель** `CargoTruck.fbx`: Y вверх, кабина на +Z, см; в сцене масштаб ×3.186 → 21.3 × 5.35 × 7.72 м.
  Точка CSV цели — передний край кабины, 3 м над дорогой.

## Результаты (полный прогон, YOLO обучена на этих же видео)

Ошибка относительно CSV цели, м (медиана / p95 / максимум):

| Вариант | положение | скачок скорости между кадрами, макс. |
|---|---|---|
| Офлайн, центр маски, начальный сплайн | 11.08 / 17.32 / 19.67 | 204 м/с² |
| Офлайн, коробка по всему видео, передняя грань | 3.30 / 8.73 / 13.79 | 137 м/с² |
| Реальное время, коробка 16.5 × 2.55 × 4 м | 5.81 / 15.84 / 23.80 | 12 м/с² |
| **Реальное время, 3D-модель, точка CSV** | **2.20 / 7.14 / 9.34** | **12 м/с²** |
| Реальное время, 3D-модель, центр кабины | 3.65 / 7.70 / 10.94 | 12 м/с² |

Центр кабины отличается от точки CSV на расстояние между ними (~2.7 м вдоль), поэтому его ошибка
относительно CSV больше. Трекер — 1 мс на кадр.

## Известные ограничения

- YOLO дообучена на этих же видео: качество детекции оценено на обучающих данных.
- Положение точки CSV на модели (передний край кабины, 3 м) найдено по CSV цели; масштаб ×3.186
  подтверждается и без CSV (лучшее совпадение с рамками YOLO при ×3.0–3.19). Стоит сверить с актором в Unreal.
- Пределы ускорения и СКО ребра рамки (20 px) подобраны под эту сцену: грузовик в ней разгоняется
  и поворачивает резче реального.
- Слабые места трекера: медленный резкий поворот (кадры ~650–850, ошибка курса десятки градусов)
  и участок с одной камерой (кадры ~200–300).
- В этом видео нет кадров совсем без детекций, поэтому `predicted` и `partial` проверены только на синтетике (тесты).
- Маски YOLO сохраняются, но пока не используются (трекер работает по рамкам).
- Препятствия на виде сверху — оценка по лучам камер, а не геометрия сцены: тёмное — подтверждено
  двумя камерами (проверено проекцией в кадры: гора внутри петли дороги), светлое — зона, где
  препятствие может быть по одной камере (одна камера не знает расстояния; так, дерево у Cam3 попадает
  только в светлую зону). Высота не учитывается.
